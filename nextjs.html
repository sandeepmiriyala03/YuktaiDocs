Steps

  1. Install: npm install @yuktishaalaa/yuktai@5.3.9
  2. Create YuktaiClient.tsx next to your root layout and paste the first file. It must start with "use client": YuktAI uses browser APIs, and the package itself does not mark its components as client components.
  3. In layout.tsx, wrap {children} with <YuktaiClient>. Keep metadata and fonts in the layout as they are.
  4. Run npm run dev. The buttons appear at the side you chose.

Using other YuktAI components

app/staff/page.tsx
"use client"
import { YuktaiGrid, AgenticPanel } from "@yuktishaalaa/yuktai"
import { SearchIcon } from "@yuktishaalaa/yuktai/icons"

export default function Staff() {
  return (
    <main>
      <h1><SearchIcon size={28} color="#0a4a85" /> Staff</h1>
      <YuktaiGrid data={rows} columns={columns} rowKey="id" engine="auto" showSearchTime />
      <AgenticPanel defaultTab="ask" engine="rust" />
    </main>
  )
}
pages/_app.tsx (Pages Router)
import type { AppProps } from "next/app"
import { YuktAIWrapper } from "@yuktishaalaa/yuktai"

// Pages Router: everything in pages/ already runs on the client.
export default function App({ Component, pageProps }: AppProps) {
  return (
    <YuktAIWrapper position="left" launcher showAccessibility showRag engine="rust">
      <Component {...pageProps} />
    </YuktAIWrapper>
  )
}

Common problems

Symptom, cause and fix
SymptomFix
Error about hooks or window in a Server ComponentUse YuktAI only inside a file that starts with "use client" (like YuktaiClient.tsx), not directly in layout.tsx.
Type error: children is missingYuktAIWrapper must wrap your content: <YuktAIWrapper>{children}</YuktAIWrapper>, not self-closing.
Page content shows twiceRender {children} once, inside the wrapper only.
New props (launcher, showVibeCoder, engine) show type errorsDelete old hand-written declare module "@yuktishaalaa/yuktai" files (for example src/types/*.d.ts); the package ships its own types.
Old version still runningnpm ls @yuktishaalaa/yuktai, then npm install @yuktishaalaa/yuktai@latest and restart npm run dev.
Rust engine reported as "ts"The browser blocked WebAssembly (often a Content Security Policy). Allow 'wasm-unsafe-eval' in script-src; YuktAI falls back to TypeScript meanwhile, with the same results.
YuktAIWrapper props
PropWhat it does
childrenYour app (required)
position"left" (default) or "right"
launcherOne ✨ button that shows or hides the others
showAccessibility, showRag, showAgent, showVibeCoderTurn each button on. Setting showAccessibility, showVibeCoder or launcher switches every button to opt-in
engine"ts", "rust" or "auto": Ask page finds passages with the page RAG first, then the on-device model answers from them
configEngine options, for example { autoFix: false }

Older usage still works: with none of showAccessibility, showVibeCoder or launcher set, ♿ is always shown and ⚡ follows showAgent.
